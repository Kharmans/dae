# DAE v14 Bug Audit — 2026-04-08

Source code scan of `dae-14x/src/module/` for potential bugs and race conditions.
Updated 2026-04-14: re-verified against current codebase.

## Fixed

### 1. `evalInline` (async) called from sync hook — `[object Promise]` in change values
- **File:** `dae.ts`
- **Issue:** `preUpdateActiveEffectEvalInlineHook` was a synchronous `Hooks.on` handler but called `evalInline()` (async). The return value was a Promise object, producing `"[object Promise]"` in change values.
- **Fix:** Moved inline eval logic into the async lib-wrapper `_preUpdateActiveEffect` patch, which properly awaits `evalInline()`.
- **Status:** FIXED — test batch 20

### 2. `addEffectChange` fire-and-forget async calls
- **File:** `dae.ts`
- **Issue:** `addEffectChange` called async functions without `await`.
- **Fix:** Now serialized via `actionQueue.add()`.
- **Status:** FIXED

### 6. Shared `options` object mutated
- **File:** `dae.ts`
- **Issue:** Hook `options` object mutated in place, visible to other modules' hooks.
- **Fix:** Only explicit `setProperty` for `expiry-reason` remains — no longer mutating shared keys.
- **Status:** FIXED

### 9. Failed `effect.update()` aborts remaining effects in loop
- **File:** `specialDurations.ts`
- **Issue:** `setEffectsExpiryToRounds` iterated effects calling `effect.update()` — if one threw, remaining effects were skipped.
- **Status:** REMOVED — `setEffectsExpiryToRounds` no longer exists (seconds-to-rounds conversion removed in v14).

### 10. Typo in debug message
- **File:** `dae.ts`
- **Issue:** `"Doing inlinve eval"` — "inlinve" should be "inline".
- **Status:** FIXED

### 11. `daeMacro` returns after first `macro.execute` change — skips remaining changes
- **File:** `dae.ts`
- **Issue:** The `for` loop over effect changes in `daeMacro` had `return await macro?.execute(scope)` after processing a `macro.execute` or `macro.itemMacro` change, exiting the function and skipping remaining changes.
- **Fix:** Removed `return` — changed to `await macro?.execute(scope)`. The loop now continues to process remaining changes.
- **Status:** FIXED — test 19.18

## Medium Priority

### 3. Hook `changeLoop()` / `changesLoop()` not awaited — concurrent effect processing
- **File:** `dae.ts` (createActiveEffectHook ~line 620, updateActiveEffectHook ~line 800, deleteActiveEffectHook ~line 971)
- **Issue:** Hook handlers define inner async functions called without `await`. The hook returns `true` immediately while macro execution, dependent updates, status toggling, and item creation/deletion continue in the background. Rapid hook firing (e.g., bulk effect creation from aura) causes interleaving. `actionQueue` serializes some inner work, but work outside the queue runs concurrently.
- **Impact:** Ordering not guaranteed when multiple effects are created/updated/deleted in quick succession.
- **Status:** TODO — may be intentional design to avoid blocking Foundry hooks

### 4. Live collection modified during iteration in `processConditionalEffects`
- **File:** `dae.ts` (~line 2536)
- **Issue:** `for (let effect of actor.effects)` iterates a live `EmbeddedCollection`, then `actor.deleteEmbeddedDocuments("ActiveEffect", ...)` modifies it mid-loop.
- **Fix:** Collect IDs to delete during iteration, then batch-delete in a single `deleteEmbeddedDocuments` call after the loop.
- **Status:** FIXED

### 5. Cross-scene teleport fire-and-forget with no error handling
- **File:** `daeMacros.ts` (~line 123-131)
- **Issue:** `canvasReady` callback calls `socketlibSocket.executeAsGM("createToken")` chained with `.then()` for `deleteToken`, with no `.catch()`. If `createToken` succeeds but `deleteToken` fails, the token exists on both scenes. Any error was silently swallowed as an unhandled promise rejection.
- **Fix:** Added `.catch()` handler that logs via `console.error`.
- **Status:** FIXED

## Low Priority

### 7. Init macro effects could be lost if created during drain
- **File:** `dae.ts` (~line 1714-1722)
- **Issue:** `pendingInitMacroEffects` is drained with `length = 0`. Concern was that an init macro could push new entries during the drain.
- **Status:** NOT A BUG — the push sites (DAESystem.ts:583, DAEdnd5e.ts:1251) check `game.ready` before pushing. After ready, new init macros go directly to `actionQueue.add`, never to the pending array.

### 8. `finally { return true }` masks all errors
- **File:** Multiple hook handlers and wrappers
- **Issue:** Pattern ensures hooks never block Foundry operations, but some catch blocks used `console.warn` (easy to miss) and two cleanup-only finally blocks had no catch at all.
- **Fix:** All try/finally blocks now have catch blocks that log via `console.error` with a `"dae |"` prefix identifying the source. Changed `console.warn` to `console.error` in 3 catch blocks (dae.ts `_preCreateActiveEffect`, `onUpdateTarget`; DAEdnd5e.ts `preItemUpdate`). Added catch blocks to 2 cleanup-only finally blocks (dae.ts `registry.refresh` wrapper, `toggleActorStatusEffect`).
- **Status:** FIXED
